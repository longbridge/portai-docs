> 本篇回答三個問題:**我的東西放在哪(Workspace)、我能用什麼和能用多少(套餐)、誰來承擔用量(Charged By)**。理解這套體系後,平臺上所有"為什麼這個功能我看不到/用不了/被攔截"的問題都能自己找到答案。

## 一、整體架構:一句話版本

```
Workspace(承載單元) ── 繫結 → 套餐(功能範圍 + 用量額度)
```

- **Workspace = 一切發生的地方**:你的 Agent、知識庫、用量都以它為邊界
- **套餐 = 能用什麼 + 能用多少**:決定當前 Workspace 的功能範圍和用量額度

下面逐層拆解。

## 二、角色(Role):你是誰

角色描述使用者的身份來源與使用場景,平臺有兩類:

| 角色 | 說明 | 典型用法 |
|------|------|---------|
| **社群使用者** | 以個人身份使用平臺 | 個人創作、試用、分享 |
| **官方使用者** | 平臺官方人員 | 提供官方服務、運營與支援 |

注意:角色只區分**身份背景**,不直接決定功能範圍和用量上限 —— 那由所在 Workspace 的套餐決定。

## 三、Workspace(工作空間):一切發生的地方

Workspace 是平臺中承載使用行為的基本單元:

- 每個使用者對應並參與到**一個或多個** Workspace
- 所有 Agent、Workflow、執行行為與**用量消耗**均發生在 Workspace 內
- Workspace 是套餐與用量生效的**邊界**

### Workspace 的關鍵規則

| # | 規則 | 說明 |
|---|------|------|
| 1 | 一對一繫結 | 一個 Workspace 同一時刻只繫結**一個套餐** |
| 2 | 社群 Workspace 自助建立 | 普通使用者僅可建立社群 Workspace,註冊時自動啟用 Starter 套餐 |
| 3 | 官方 Workspace 由平臺建立 | 由平臺側建立或授權,普通使用者不可自行建立 |
| 4 | 能力隨 Workspace 切換 | 同一個人在不同 Workspace 中看到的功能入口自動變化 |
| 5 | 只展示可用的功能 | 使用者只感知"當前 Workspace 能做什麼",不可用的功能直接隱藏入口,無需理解背後的套餐細節 |
| 6 | 有且僅有一個 Owner | 每個 Workspace 只能有**一個 Owner**;Editor 和 Viewer 的數量取決於**套餐上的成員數量限制** |

### Workspace 成員角色

| 成員角色 | 數量 | 許可權 |
|---------|------|------|
| **Owner** | 每個 Workspace **僅一個** | 全部許可權,且**唯一**能執行訂閱購買/升級/降級/退訂等商業操作(見 4.3) |
| **Editor** | 隨套餐限制 | 建立、編輯 Workspace 內的 Agent、知識庫等資源 |
| **Viewer** | 隨套餐限制 | 檢視和使用 Workspace 內的資源,不可編輯 |

注意區分:第二節的角色(社群/官方使用者)描述的是**平臺身份**,這裡的 Owner/Editor/Viewer 是**同一 Workspace 內部**的成員許可權,二者相互獨立。

## 四、套餐(Plan):能用什麼、能用多少

套餐是平臺中可被購買或發放的**商業物件**,決定當前 Workspace 的功能範圍與用量額度。

### 4.1 三個套餐

| 套餐 | 型別 | 定位 | 價格(USD 基準)* | 獲得方式 |
|------|------|------|--------------|---------|
| **Starter** | 免費 | 個人入門 | $0 | 註冊自動啟用 |
| **Pro** | 付費 | 個人專業版 | ~$20/月 | 連續包月訂閱 |
| **Premium** | 付費 | 高階版 | ~$100/月 | 連續包月訂閱 |

> \* 價格可能會**動態調整**,以實際收費為準。

### 4.2 套餐權益差異速查

| 權益 | Starter | Pro | Premium |
|------|---------|-----|---------|
| 月度用量額度 | 基礎額度 | 更高額度 | 最高額度(具體以套餐頁即時展示為準) |
| Agent 建立(Agentic Chat / Chatflow) | ✓ | ✓ | ✓ |
| 內建工具 | 部分 | 全量 | 全量 |
| 第三方 MCP Server | ✗ | ✗ | ✓ |
| OpenAPI 工具(自行配置) | ✓ | ✓ | ✓ |
| 自定義 Skill 數量 | 3 | 20 | 100 |
| 官方內建 Skill(財報分析等) | ✗ | ✓ | ✓ |
| 知識庫容量 | 50MB | 5GB | 20GB |
| 釋出 Agent 到廣場 | ✗ | ✓(需安全掃描) | ✓(需安全掃描) |
| 使用/Fork 廣場 Agent | ✓ | ✓ | ✓ |

> **⚠️ 套餐權益以實際權益為準**:本幫助文件的更新可能滯後,本節的定價與權益內容可能與實際權益存在**較大差異**,一切以產品內套餐頁即時展示為準。運營側調整套餐配置時,存量使用者當前計費週期內不受變更影響。

### 4.3 訂閱規則要點

- **統一連續包月**,不提供單月購買(與主流 AI 產品一致)
- 支付渠道:iOS 走 Apple IAP,Android/Web 走 Stripe;同一 Workspace 同一時刻只能有一個活躍訂閱渠道
- **僅 Workspace Owner** 可執行購買 / 升級 / 降級 / 退訂操作
- **升級**:立即生效,按渠道規則補差價
- **降級**:次月生效,生效前可撤回;當前用量週期保持原額度,下週期按新套餐
- **退訂**:到期前可恢復自動續費;到期後回落到 Starter
- 幣種在首次購買時鎖定,各地區定價見 [1.6 分地區服務說明](regions)

## 五、用量(Usage):怎麼計、怎麼扣

> **用量在長橋 AI 產品間通用**:同一使用者的額度**同時適用於官方 Chatbot(LongbridgeAI 對話端)和 Agent Platform** —— 在 Chatbot 裡問答與在平臺上執行 Agent,消耗的是同一份額度。

### 5.1 什麼行為消耗用量

系統對 5 種計費單元即時採集,統一換算為 USD:

| 計費單元 | 計量方式 |
|---------|---------|
| LLM 呼叫 | 按模型返回的 input/output token 數 |
| Embedding(知識庫向量化) | 按處理的 token 數 |
| Rerank | 按處理的 token 數 |
| 沙箱執行(Code 節點等) | 按執行時長,向上取整到分鐘 |
| 搜尋/爬蟲工具 | 按呼叫次數(僅特定搜尋和爬蟲工具計費,OpenAPI 等不計費) |

### 5.2 額度的發放節奏:月度總額 + 周滾動釋放

- **月度總額度**:每個計費週期(月)分配總額度;週期結束時歸零,新週期重新分配,**不結轉**
- **周滾動釋放**:月度額度按每 7 天滾動釋放,每週可用 ≈ 月度總額 ÷ 4;當週用完需等下一個滾動周,當週沒用完也**不順延**
- 用量週期獨立滾動,與訂閱週期(續費日)無關
- 套餐額度之外,還可能持有**權益卡**(限時按更高檔位提升功能權益併疊加用量,不改變訂閱關係),見 [1.8 HKSG 權益卡](hksg-benefits)

> 設計意圖:防止一天燒光整月額度,讓消耗節奏可控。

### 5.3 超額了會怎樣

超額後會被攔截;是否提供用量提前預警(如 80%/90% 提示)**以實際線上情況為準**:

| 場景 | 攔截行為 |
|------|---------|
| 對話/Workflow/試執行等執行類 | 執行前檢查剩餘額度,不足則阻止本次執行並提示升級套餐 |
| 知識庫容量超限 | 禁止新增檔案;超限檔案**按上傳時間從最舊開始**標記為**停用**(不參與檢索),不自動刪除,刪檔案或升級可恢復 |
| Skill 數量超限 | 阻止建立新 Skill,提示刪除已有或升級;權益卡到期回落導致的超限,已有內容保留、僅不能新增(見 [1.8](hksg-benefits)) |

### 5.4 誰來承擔用量(Charged By)

一次執行消耗的用量記在誰頭上,取決於 Agent 歸屬和你與該 Workspace 的成員關係:

```
使用者 A(歸屬 Workspace A)使用某個 Agent 時:
├─ Agent 屬於 Workspace A(自己的)      → Workspace A 承擔
├─ Agent 屬於 Workspace B,A 是 B 的成員 → Workspace B 承擔(開發者付費)
├─ Agent 屬於 Workspace B,A 不是成員    → Workspace A 承擔(使用者付費)
└─ 系統行為(AI 輔助建立、合規校驗等)     → 平臺承擔,不扣任何使用者額度
```

幾個具體場景:

| 場景 | 承擔方 |
|------|--------|
| 正式對話執行 | 按上面的歸屬規則 |
| Agent 整體試執行 / 節點試執行 | 開發者(自己除錯自己付) |
| 上下文壓縮、長期記憶讀寫 | 與對話執行一致 |
| AI 輔助建立 Agent、合規校驗 | 平臺 |

### 5.5 配置時 vs 執行時:一個容易混淆的點

**使用者的套餐隻影響用量額度,不影響 Agent 已具備的功能。**

| 階段 | 判定依據 | 決定什麼 |
|------|---------|---------|
| **配置時**(開發者搭 Agent) | Agent 所屬 Workspace 的套餐 | 開發者能在編輯器裡選到哪些工具、Skill、MCP |
| **執行時**(使用者用 Agent) | Agent 已配置的功能 + 內容層鑑權 | 使用者直接可用,功能繼承自 Agent 所屬 Workspace,不受自己套餐限制 |

例:Premium 開發者在 Agent 裡配置了第三方 MCP 工具,Starter 使用者使用這個 Agent 時**照樣能用**該工具 —— 只是消耗的是自己 Workspace 的用量額度(若按使用者付費)。

## 六、模型分級與用量的關係

- 模型分為「**主流**」和「**SOTA**」兩級;SOTA 模型有明確標識,單位消耗更高
- Chatflow/Workflow 支援**節點級模型配置**:簡單任務(分類、格式化)用主流模型,核心推理用 SOTA,是控制用量最有效的手段
- 部分模型因廠商條款限制僅平臺官方可用,普通套餐的模型選擇器中不會展示

## 七、常見問題

| 問題 | 答案 |
|------|------|
| 為什麼我在編輯器裡看不到某個工具? | 當前 Workspace 的套餐不含該工具(如第三方 MCP 需 Premium) |
| 為什麼同事能用的功能我沒有? | 你們所在的 Workspace 不同,能力隨 Workspace 變化 |
| 額度還有但執行被攔截? | 可能是當前 7 天滾動周的額度用完了,月度餘額要等下個滾動周釋放 |
| 用別人廣場上的 Agent 扣誰的量? | 你不是對方 Workspace 成員時,扣你自己的(使用者付費) |
| 試執行收費嗎? | 收,消耗開發者自己 Workspace 的額度;但 AI 輔助建立、合規校驗由平臺承擔 |
| 想要更高額度/更多功能? | Workspace Owner 在套餐頁升級,立即生效 |
