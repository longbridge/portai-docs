> **位置**:模型配置與節點異常處理相關設定
> 生產環境的 Agent 不能因為某個模型廠商抖動、某次呼叫失敗就整體不可用。平臺提供一組容災能力，讓 Agent 在異常情況下仍能穩定輸出。

## 模型跨廠商呼叫

**是什麼**:同一個模型 (相同模型名) 往往在多個廠商/多個賬號下都有部署。開啟**跨廠商呼叫**後，當模型呼叫失敗觸發重試時，系統可**切換到其他已啟用廠商下相同模型名的賬號**繼續呼叫。

- 主賬號所在廠商故障、限流時，自動切換備用廠商，使用者側幾乎無感
- 切換僅發生在**相同模型名**之間，不會悄悄換成別的模型 —— 輸出能力和風格保持一致
- 前提：目標廠商賬號已在平臺啟用

**適用場景**:面向客戶的生產 Agent 建議開啟，單廠商故障不再是單點故障。

## 模型組合

**是什麼**:系統提供**預設的模型組合方案**(如「高性價比組合」「高效能組合」),也支援自行選擇單個模型。

**容災意義**:模型組合在提升價效比之外，也降低了對單一模型的依賴 —— 組合內多模型互為備份，避免把所有節點綁死在一個模型上。

**搭配建議**:配合**節點級模型配置**使用 (不同節點選不同模型),關鍵鏈路與非關鍵鏈路分散到不同模型，進一步隔離風險。

## 失敗時重試

**是什麼**:模型或工具呼叫失敗時，系統支援**自動重試**,而不是一次失敗即終止。

- 重試與「跨廠商呼叫」聯動：開啟跨廠商後，重試時可切換廠商賬號，而不是在故障廠商上反覆撞牆
- 用量計費以實際發生的呼叫為準：已傳送至模型的請求按實際 token 消耗計費，未傳送的不計費

## 異常處理

呼叫失敗後流程怎麼走，由異常處理機制決定：

| 場景 | 處理方式 |
|------|---------|
| **LLM 呼叫失敗** | 流程可根據配置選擇**繼續或中斷**執行;已傳送部分按實際消耗計費，失敗不觸發額度回滾 |
| **Tool 呼叫失敗** | 工具失敗本身不影響結算;未觸發模型推理則不消耗用量 |
| **Iteration 單項失敗** | 配置錯誤處理後，**單個元素失敗不中斷整體**,其餘元素正常產出 (見 [Iteration 節點](../nodes/iteration)) |
| **使用者主動終止 / 系統異常中斷** | 已發生的消耗不回滾，未執行部分不計費，流程進入終止態可供審計 |

## 生產 Agent 的容災配置清單

- [ ] 核心模型開啟**跨廠商呼叫**(確認備用廠商賬號已啟用)
- [ ] 關鍵呼叫配置**失敗重試**
- [ ] 批次任務 (Iteration) 配置**錯誤處理**,單項失敗不拖垮整體
- [ ] LLM/Tool 失敗時的分支行為已設計 (繼續 / 中斷 / 兜底話術),不讓使用者看到裸報錯
- [ ] 用三類異常用例實測過：廠商故障 (可用切換驗證)、工具超時、批次任務部分失敗
