## 節點概述

**節點英文名**: Http Request  
**節點中文名稱**: Http 請求  
**支援場景**: Chatflow Agent（支援）, Workflow Agent（支援）  

## 功能說明

Http Request 節點用於訪問 Http 的介面，獲取資料。它提供了強大的 HTTP 請求能力，支援各種 HTTP 方法和請求配置，能夠與外部 API 進行互動，獲取和處理資料。

## 節點編輯區域

![HTTP 請求編輯面板:API(請求方法 + URL，支援插入變數與匯入 cURL)、HEADERS/PARAMS 鍵值對、BODY 型別 (none/form-data/x-www-form-urlencoded/json/raw-text),輸出變數 body/status_code/headers/files](./images/15-2-%E8%8A%82%E7%82%B9%E9%85%8D%E7%BD%AE.png)

### 1. API 配置
- **請求方法**: 下拉選擇 HTTP 方法（GET、POST、PUT、DELETE、PATCH 等）
- **請求 URL**: 設定目標 API 的 URL 地址，輸入 `/` 可插入變數
- **匯入 cURL**: 支援貼上 cURL 命令一鍵生成請求配置

### 2. HEADERS / PARAMS
- **HEADERS**: 以鍵值對方式配置 HTTP 請求頭（需要鑑權的介面在此配置，如 `Authorization: Bearer <token>`）
- **PARAMS**: 以鍵值對方式配置 URL 查詢引數

### 3. BODY 配置
- **型別選擇**: none / form-data / x-www-form-urlencoded / json / raw-text
- **請求體**: 根據所選型別設定請求體內容

### 4. 輸出變數
- **body** (string): 響應內容
- **status_code** (number): 響應狀態碼
- **headers** (object): 響應頭列表 JSON
- **files** (array[file]): 檔案列表

### 5. 下一步配置
- 支援新增下一個節點

## HTTP 方法支援

### 1. GET 請求
- **用途**: 獲取資料
- **特點**: 無請求體，引數通過 URL 傳遞
- **示例**: 獲取使用者資訊、查詢資料

### 2. POST 請求
- **用途**: 建立資料
- **特點**: 有請求體，用於提交資料
- **示例**: 建立使用者、提交表單

### 3. PUT 請求
- **用途**: 更新資料
- **特點**: 完整更新資源
- **示例**: 更新使用者資訊、修改配置

### 4. DELETE 請求
- **用途**: 刪除資料
- **特點**: 刪除指定資源
- **示例**: 刪除使用者、移除資料

### 5. PATCH 請求
- **用途**: 部分更新
- **特點**: 只更新部分欄位
- **示例**: 更新使用者狀態、修改部分資訊

## 鑑權說明

節點沒有獨立的認證配置區，需要鑑權的介面通過 **HEADERS / PARAMS** 配置：

- **Basic Auth**: HEADERS 中新增 `Authorization: Basic base64(username:password)`
- **Bearer Token**: HEADERS 中新增 `Authorization: Bearer <token>`
- **API Key**: 按介面要求放入 HEADERS 或 PARAMS 中傳遞

## 常見問題

### Q: 如何處理認證失敗？
A: 檢查 HEADERS 中的認證頭格式與憑證是否正確（如 Bearer Token 是否有效、是否過期）。

### Q: 如何除錯 HTTP 請求？
A: 使用試執行功能，檢視請求和響應詳情，檢查狀態碼和錯誤資訊。

### Q: BODY 支援哪些型別？
A: none、form-data、x-www-form-urlencoded、json、raw-text 五種。

## 注意事項

1. **URL 編碼**: 確保 URL 引數正確編碼
2. **請求頭**: 設定正確的 Content-Type
3. **認證資訊**: 保護認證資訊的安全，避免在提示詞或輸出中洩露
4. **錯誤處理**: 用 status_code 判斷結果，為失敗情況設計兜底分支
