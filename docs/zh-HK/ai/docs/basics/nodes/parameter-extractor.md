## 節點概述

**節點英文名**: Parameter Extractor  
**節點中文名稱**: 引數提取器  
**支援場景**: Chatflow Agent（支援）, Workflow Agent（支援）  

## 功能說明

引數提取器節點利用大模型從自然語言文本中**提取結構化引數**：配置要提取的引數定義（或直接從工具匯入入參定義），模型從輸入變數中識別並抽取對應的值，輸出供後續節點使用——最典型的場景是把使用者的自然語言請求轉換為下游 Tool 節點所需的呼叫引數。

## 節點編輯區域

![引數提取器編輯面板：模型、輸入變數、提取引數 (可從工具匯入)、指令、失敗時重試與異常處理](./images/13-2-%E8%8A%82%E7%82%B9%E9%85%8D%E7%BD%AE.png)

### 1. 模型配置
- **模型選擇**: 必填，同 LLM 節點的模型配置方式——引數提取由該模型完成

### 2. 輸入變數
- **變數選擇**: 輸入 `/` 插入變數，選擇要從中提取引數的來源文本 (如 `開始/sys.query` 或上游節點輸出)

### 3. 提取引數
- **新增引數**: 點選 `+` 手動定義要提取的引數 (引數名、型別、說明、是否必填)
- **從工具中匯入**: 一鍵匯入某個工具的入參定義作為提取目標——**典型用法**:先用引數提取器從使用者自然語言中提取出工具需要的引數，再傳給下游 Tool 節點呼叫

### 4. 指令
- **附加指令**: 可編寫提取的補充指令 (如格式要求、歧義處理規則),編輯器同 LLM 節點的 Prompt 輸入，支援 `/` 插入變數

### 5. 容錯配置
- **失敗時重試**: 開關，提取失敗時自動重試
- **異常處理**: 下拉選擇異常處理策略 (預設「無」)

### 6. 下一步配置
- 支援新增下一個節點

## 使用場景

### 1. 自然語言轉工具引數（最典型）
- 使用者說「幫我看下特斯拉最近兩週的新聞」→ 提取 `symbol="TSLA.US"`、`days=14` → 傳給下游 Tool 節點呼叫
- 配合「從工具中匯入」：直接以工具入參定義為提取目標，無需手工建引數

### 2. 結構化資訊收集
- 從使用者的自然語言或多輪對話文本中提取姓名、日期、金額等結構化欄位
- 提取結果供 IF Else 分支判斷、Code 節點加工或 Answer 節點引用

### 3. 歧義與預設值處理
- 在「指令」中約定歧義處理規則（如「未指明市場時預設美股」「日期相對錶述換算為絕對日期」）

## 常見問題

### Q: 提取不準確怎麼辦？
A: 把引數的「說明」寫得更具體（含格式與示例）、在指令中補充規則，或更換能力更強的模型（參考 2.5 技巧二）。

### Q: 如何與工具節點配合？
A: 用「從工具中匯入」一鍵匯入工具入參定義，提取結果的欄位即可直接對接下游 Tool 節點。

### Q: 提取失敗或欄位缺失怎麼辦？
A: 開啟「失敗時重試」，並按流程重要性配置「異常處理」策略；必填引數建議在下游增加兜底判斷。

## 注意事項

1. **模型必填**: 提取由所選模型完成，提取質量取決於模型能力
2. **引數說明質量**: 引數名、型別、說明寫得越清楚，提取越準確
3. **容錯配置**: 重要流程務必配置失敗重試與異常處理
4. **來源文本**: 輸入變數應指向包含目標資訊的文本（如 sys.query 或上游輸出）
