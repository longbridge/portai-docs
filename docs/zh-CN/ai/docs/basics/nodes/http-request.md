## 节点概述

**节点英文名**: Http Request  
**节点中文名称**: Http请求  
**支持场景**: Chatflow Agent（支持）, Workflow Agent（支持）  

## 功能说明

Http Request节点用于访问Http的接口，获取数据。它提供了强大的HTTP请求能力，支持各种HTTP方法和请求配置，能够与外部API进行交互，获取和处理数据。

## 节点编辑区域

![HTTP 请求编辑面板:API(请求方法 + URL,支持插入变量与导入 cURL)、HEADERS/PARAMS 键值对、BODY 类型(none/form-data/x-www-form-urlencoded/json/raw-text),输出变量 body/status_code/headers/files](./images/15-2-%E8%8A%82%E7%82%B9%E9%85%8D%E7%BD%AE.png)

### 1. API 配置
- **请求方法**: 下拉选择 HTTP 方法（GET、POST、PUT、DELETE、PATCH 等）
- **请求URL**: 设置目标 API 的 URL 地址，输入 `/` 可插入变量
- **导入 cURL**: 支持粘贴 cURL 命令一键生成请求配置

### 2. HEADERS / PARAMS
- **HEADERS**: 以键值对方式配置 HTTP 请求头（需要鉴权的接口在此配置，如 `Authorization: Bearer <token>`）
- **PARAMS**: 以键值对方式配置 URL 查询参数

### 3. BODY 配置
- **类型选择**: none / form-data / x-www-form-urlencoded / json / raw-text
- **请求体**: 根据所选类型设置请求体内容

### 4. 输出变量
- **body** (string): 响应内容
- **status_code** (number): 响应状态码
- **headers** (object): 响应头列表 JSON
- **files** (array[file]): 文件列表

## HTTP方法支持

### 1. GET请求
- **用途**: 获取数据
- **特点**: 无请求体，参数通过URL传递
- **示例**: 获取用户信息、查询数据

### 2. POST请求
- **用途**: 创建数据
- **特点**: 有请求体，用于提交数据
- **示例**: 创建用户、提交表单

### 3. PUT请求
- **用途**: 更新数据
- **特点**: 完整更新资源
- **示例**: 更新用户信息、修改配置

### 4. DELETE请求
- **用途**: 删除数据
- **特点**: 删除指定资源
- **示例**: 删除用户、移除数据

### 5. PATCH请求
- **用途**: 部分更新
- **特点**: 只更新部分字段
- **示例**: 更新用户状态、修改部分信息

## 鉴权说明

节点没有独立的认证配置区，需要鉴权的接口通过 **HEADERS / PARAMS** 配置：

- **Basic Auth**: HEADERS 中添加 `Authorization: Basic base64(username:password)`
- **Bearer Token**: HEADERS 中添加 `Authorization: Bearer <token>`
- **API Key**: 按接口要求放入 HEADERS 或 PARAMS 中传递

## 常见问题

### Q: 如何处理认证失败？
A: 检查 HEADERS 中的认证头格式与凭证是否正确（如 Bearer Token 是否有效、是否过期）。

### Q: 如何调试HTTP请求？
A: 使用试运行功能，查看请求和响应详情，检查状态码和错误信息。

### Q: BODY 支持哪些类型？
A: none、form-data、x-www-form-urlencoded、json、raw-text 五种。

## 注意事项

1. **URL编码**: 确保URL参数正确编码
2. **请求头**: 设置正确的Content-Type
3. **认证信息**: 保护认证信息的安全，避免在提示词或输出中泄露
4. **错误处理**: 用 status_code 判断结果，为失败情况设计兜底分支
